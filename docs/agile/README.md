# DAGent — Agile Project Documentation

This package describes how the DAGent project was built and how it would be managed under an Agile framework. It was produced by **analysing the repository** (Git history, source, configuration and the working tree as of **2026-10-28**), not from team interviews. It is a *reconstruction*, and it says so wherever it is one.

> **Important caveats**
> 1. The team left **no** record of sprints, a Kanban board, meetings, reviews or retrospectives. The methodology, board, sprints and retrospective here are **recommendations** ([PROPOSED]); the observed process is described separately in [agile-methodology](agile-methodology.md) §1.
> 2. The team lead states there are **three members** — M1 Vishakha Sharma, M2 Prajinraj Ranawat, M3 Fatema Shakir — but the repository contains Git identities for **M1 and M2 only**. M3's contribution cannot be shown from Git; see [team-verification-checklist](team-verification-checklist.md) A7.
> 3. A large body of work (66 changed files, 2026-10-28) is **uncommitted** and was produced in an **AI-assisted session**; it is attributed to `AI-S1`, not to a team member ([team-contributions](team-contributions.md) §4). This documentation package was also generated by an AI assistant and must be reviewed by the team before submission.
> 4. Remote GitHub issues, pull requests and Projects were **not queried**.

## Evidence labels

| Label | Meaning |
|---|---|
| **[VERIFIED]** | Directly supported by repository contents, commits or reproducible command output |
| **[PARTIALLY VERIFIED]** | Some support exists, but the full claim cannot be established (e.g. observed once in a session, not reproducible from the repo) |
| **[TEAM CONFIRMATION REQUIRED]** | Only the project members can confirm it |
| **[PROPOSED]** | A recommendation or reconstructed plan — **not** a historical event |
| **[UNKNOWN]** | The available evidence is insufficient |
